# Динамические контейнеры C++: Вектор и Строка

В стандартную библиотеку C++ входят базовые контейнеры `std::vector` (вектор) и `std::string` (строка). Главная их особенность заключается в том, что все элементы размещаются в памяти сплошным непрерывным массивом.

Это гарантирует:
* Мгновенный доступ к произвольному элементу по его индексу за константное время $O(1)$.
* Быстрое и эффективное добавление новых элементов в конец контейнера.

---

## Контейнер `std::vector`

`std::vector` представляет собой динамический массив, способный автоматически расширять выделенный объем памяти по мере добавления данных. Контейнер самостоятельно занимается выделением и освобождением памяти, предотвращая утечки ресурсов.

Для работы с этим контейнером необходимо подключить заголовочный файл:

### Однородность типов и шаблоны

Вектор может хранить только элементы одного и того же типа, который определяется на этапе компиляции. Этот тип указывается в угловых скобках:
* `std::vector<int>` — вектор целых чисел;
* `std::vector<std::string>` — вектор текстовых строк.

> [!NOTE]  
> Обозначение `std::vector` — это не самостоятельный тип данных, а **шаблон класса** (`class template`). Полноценным типом он становится только после того, как в него подставляют конкретный тип элементов.

---

### Особенности индексации

* **Запрет отрицательных индексов:** В C++ нельзя обращаться к элементам с конца через отрицательные индексы (как это сделано в Python).
* **Принцип нулевых издержек:** Обращение к элементам через оператор `[]` не выполняет никаких проверок выхода за границы. Это экономит ресурсы и следует философии C++ (*«не платишь за то, чем не пользуешься»*). За корректность индексов ($0 \le i < \text{размер}$) полностью отвечает разработчик.

> [!WARNING]  
> **Неопределенное поведение (UB):** Попытка чтения или записи по невалидному индексу приводит к выходу за пределы массива и некорректной работе программы.

---

### Размерность и канонический цикл

Размер контейнера и индексы в C++ представлены беззнаковым типом. Стандарт определяет псевдоним `size_t` (или `std::vector<T>::size_type`), битовая ширина которого зависит от целевой архитектуры (32 или 64 бита).

Обход вектора по индексам принято оформлять в виде **канонического цикла**:

cpp

for (size_t i = 0; i != data.size(); ++i) {

    // Операции с data[i]

}

## Особенности использования и работа с памятью

### 1. Риски беззнакового типа в `size()`

Метод `.size()` возвращает беззнаковый тип (`size_t`). В C++ любые операции с участием знаковых и беззнаковых типов автоматически приводят результат к **беззнаковому типу**.

> [!WARNING]  
> **Опасность вычитания из `size()`:**  
> В выражении `data.size() - 1` для пустого вектора (`size() == 0`) вместо `-1` получится максимально возможное число для данного типа (на 64-битной платформе это $2^{64} - 1 = 18\,446\,744\,073\,709\,551\,615$). Если использовать такое выражение в циклах, произойдет сбой программы из-за выхода за пределы памяти.

---

### 2. Производительность операций

Местоположение элементов в непрерывной памяти определяет скорость выполнения операций:

* **Добавление и удаление с конца (`push_back` / `pop_back`):** выполняются мгновенно за $O(1)$.
* **Вставка и удаление из начала или середины:** требуют сдвига всего остального массива, поэтому работают за $O(n)$.
* Вектор не имеет специализированных функций `push_front` и `pop_front`. Для произвольных вставок применяются методы `.insert()` и `.erase()` в сочетании с итераторами.
* Для полной очистки вектора от данных применяется метод `.clear()`.

---

### 3. Управление памятью: Резерв и Реаллокация

Вектор управляет выделенной памятью гибко, запрашивая у системы объём с запасом.

* **Реаллокация:** При заполнении выделенного блока вектор запрашивает новый фрагмент памяти (обычно в 1.5–2 раза больше предыдущего), копирует туда существующие элементы и освобождает старый участок.
* **Амортизированная сложность:** За счет пропорционального роста буфера средняя (амортизированная) сложность добавления нового элемента остается равной $O(1)$.

#### Сравнение `size()` и `capacity()`

| Метод | Описание |
| :--- | :--- |
| `data.size()` | Число фактически записанных элементов в векторе |
| `data.capacity()` | Полный размер выделенной памяти (в единицах элементов) |

---

### 4. Различия `reserve()` и `resize()`

Не следует путать предварительное выделение памяти и изменение физического количества элементов:

cpp

// 1. reserve() — выделяет память под N элементов (size остается равен 0)

std::vector a;

a.reserve(100); // size = 0, capacity = 100

// 2. resize() — физически меняет количество элементов в векторе

std::vector b;

b.resize(100);  // size = 100, capacity >= 100 (новые элементы заполняются нулями)

#### Лексикографическое сравнение
Оператор `<` по умолчанию сравнивает векторы **поэлементно (лексикографически)** — аналогично сравнению строк в словаре. Это позволяет автоматически сортировать двумерные массивы и списки векторов:

cpp

std::vector> matrix = {{2, 3}, {1, 9}, {1, 4}};

std::sort(matrix.begin(), matrix.end());

// Результат: {{1, 4}, {1, 9}, {2, 3}}
